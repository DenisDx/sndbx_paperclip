# Paperclip VM for sndbx

## What this machine is

This is a self-contained sndbx virtual machine that runs one self-hosted
[Paperclip](https://github.com/paperclipai/paperclip) instance. Paperclip is the
control plane ("the company") that orchestrates teams of AI agents; an OpenClaw
instance running on another machine can act as one of its agents ("the
employee").

Paperclip is built from a pinned upstream source revision directly into the
image. The Node.js server, the React UI, and an embedded PostgreSQL database all
run in a single container. Every persistent artifact (database, uploads, agent
workspaces, configuration, secrets) lives in the host `data/` directory, which
is bind-mounted at `/paperclip` and is the application home (`PAPERCLIP_HOME`).
Copying `data/` to another checkout moves the whole instance.

The container starts as root, remaps its internal `node` account to
`PAPERCLIP_UID:PAPERCLIP_GID` (default `1000:1000`), repairs ownership of
`/paperclip`, then drops privileges and runs Paperclip as `node`. Files created
under `data/` therefore belong to the configured user. Point these variables at
the user that runs `sndbx` (`id -u` / `id -g`).

The VM ships an sndbx lifecycle hook (`app.py`) that repairs persistent
ownership and starts key-only SSH for `node` on guest port 22.

### Configuration files

| File | Responsibility |
| --- | --- |
| `Dockerfile` | Base image, pinned Paperclip revision, build steps, runtime defaults, SSH policy. |
| `.env` / `.env.example` | Private runtime identity (`PAPERCLIP_UID`/`PAPERCLIP_GID`), ports, public URL, deployment mode, `BETTER_AUTH_SECRET`, optional model provider keys including `OPENCODE_API_KEY`. `.env` is ignored by Git and mounted read-only into the container. |
| `docker/load-paperclip-env.sh` | Loads `.env` inside the container while letting sndbx/Compose deployment values (`PAPERCLIP_BIND_HOST`, `PAPERCLIP_PORT`, `PAPERCLIP_PUBLIC_URL`, `PAPERCLIP_UID`, `PAPERCLIP_GID`) win. |
| `docker/entrypoint.sh` | Applies UID/GID remapping and ownership repair, then starts the app as `node`. |
| `docker/start-paperclip.sh` | Default launcher; runs `data/config/start.sh` when present. |
| `data/config/start.sh.example` | Optional startup override (copy to `start.sh` to customize the launch command). |
| `app.py` | sndbx lifecycle hook: ownership repair plus key-only SSH. |
| `docker-compose.yml` | Standalone Docker Compose deployment (mounts, ports, tmpfs). |
| `sndbx.overlay.json5` | sndbx sandbox overlay; the host merges it under the root configuration. |
| Root sndbx `config.json5` and `.env` | After merge: sandbox registration and the resolved `PAPERCLIP_HOST_ROOT` path. |

## Installing into sndbx

The image source is a standalone repository:
<https://github.com/DenisDx/sndbx_paperclip>.

### 1. Clone it into the sndbx checkout

The directory name must be `paperclip` so it matches `local_image_id`.

```bash
cd "$SNDBX_ROOT/images"
git clone https://github.com/DenisDx/sndbx_paperclip.git paperclip
```

### 2. Configure the private environment and public origin

The cloned repository does not contain `.env` (it is ignored). Run the sndbx
configuration helper to create it, generate its session secret, and prompt for
the host/IP or complete URL that browsers use to reach Paperclip:

```bash
cd "$SNDBX_ROOT/images/paperclip"
./configure_sndbx.sh "$SNDBX_ROOT"
```

For example, entering `paperclip.example.test` configures
`http://paperclip.example.test:13100`; entering an `http://` or `https://` URL
preserves its scheme and port. The helper writes matching `PAPERCLIP_PUBLIC_URL`,
`PAPERCLIP_ALLOWED_HOSTNAMES`, `BETTER_AUTH_URL`, and
`BETTER_AUTH_TRUSTED_ORIGINS` values to both environment files. It also sets
`PAPERCLIP_HOST_ROOT` in the root sndbx `.env`. Add any required model provider
keys to `images/paperclip/.env` afterwards.

### 3. Register the sandbox in sndbx

Then merge the two blocks from `sndbx.overlay.json5` into the root
`$SNDBX_ROOT/config.json5`:

- the `"paperclip"` entry under `sandboxes.items`;
- the `"paperclip-env-token"` entry under `envids`.

Override the defaults from the root `.env` if needed (`PAPERCLIP_HOST_PORT`,
`PAPERCLIP_SSH_HOST_PORT`, `PAPERCLIP_MEMORY`, `PAPERCLIP_CPUS`).

### 4. Build the image

sndbx auto-builds a configured local image on first use when it is missing, but
it can also be built explicitly:

```bash
cd "$SNDBX_ROOT/images/paperclip"
docker build -t paperclip:latest .
```

### 5. Load the configuration and start the sandbox

Reload sndbx so it reads the merged configuration, then start the `paperclip`
sandbox from the Web UI dashboard or an MCP tool. To have it start with sndbx,
set `run_at_startup: true` in the merged block.

```bash
# Reload without touching other running sandboxes:
systemctl --user kill --kill-whom=main --signal=SIGKILL sndbx.service || \
  sudo systemctl restart sndbx.service
```

Because the container remaps to `PAPERCLIP_UID` (which you set to the sndbx
runner), data files are owned by that user and no ACL scripts are required for
the sndbx path. `prepare_host_permissions.sh` is only needed for the standalone
Docker Compose workflow or when running under a different identity.

### Optional: SSH access

Add public keys to the sandbox's `ssh_keys` list, then restart or recreate it,
and connect through the published port:

```json5
ssh_keys: [
  "ssh-ed25519 AAAA... operator@example",
],
```

```bash
ssh -p 12022 node@127.0.0.1
```

## Connecting an OpenClaw instance

### OpenClaw manages Paperclip (outbound API)

Publish Paperclip's API (already done by `PAPERCLIP_HOST_PORT`, default `13100`)
and point the remote OpenClaw agent at it:

```bash
export PAPERCLIP_API_URL="http://<paperclip-host>:13100"
export PAPERCLIP_API_KEY="<board or agent API key>"
curl -H "Authorization: Bearer ${PAPERCLIP_API_KEY}" "${PAPERCLIP_API_URL}/api/health"
```

All endpoints are relative to `/api`. Create API keys in the Paperclip UI, or
read the machine-readable surface at `GET /api/openapi.json`.

### Paperclip orchestrates OpenClaw (inbound adapter)

Paperclip drives a remote OpenClaw gateway through the `openclaw_gateway`
adapter, which speaks the OpenClaw Gateway WebSocket protocol. Configure an
agent with:

- `url`: `ws://` or `wss://` address of the remote gateway (for example
  `wss://<openclaw-host>:<gateway-port>/`). When the gateway is behind a TLS
  proxy that uses an internal certificate authority, trust that root
  certificate.
- `authToken` (or `headers["x-openclaw-token"]`): the remote gateway token.
- `autoPairOnFirstConnect` (default true) handles the one-time device pairing.

The Paperclip VM needs outbound network access to the OpenClaw host; sndbx
sandboxes have unrestricted networking by default.

## Running with Docker Compose (optional)

Choose either this standalone deployment or the sndbx sandbox for one checkout.
Do not run both against the same `data/` directory: they conflict on the
published ports and can concurrently access the embedded PostgreSQL data.

> **WARNING:** `./install.sh` is only for the standalone Docker Compose mode.
> Do not run it when this checkout is managed by sndbx.

The same image can run outside sndbx:

```bash
cd "$SNDBX_ROOT/images/paperclip"
./install.sh   # asks for the public origin, creates .env + secret, then deploys
```

Open `http://localhost:13100/`, create the first board account, and configure
agents.

## Safety

The service runs as an unprivileged `node` account. `.env`, the
`BETTER_AUTH_SECRET`, agent API keys, and provider keys live under `data/` and
in `.env`; both are ignored by Git. Never publish `data/` or `/paperclip` as a
whole.

## Updates and backup

To update Paperclip, change `PAPERCLIP_REF` in the `Dockerfile`, rebuild the
image, and recreate the sandbox. Do not run `apt upgrade` inside a running VM.

For a consistent backup, stop the service, then copy `data/` preserving owners,
groups, ACLs, extended attributes, and dotfiles:

```bash
docker compose stop paperclip
rsync -aAX --numeric-ids data/ /backup/paperclip-data/
docker compose up -d
```

If `data/` was copied without metadata, run `sudo ./run_after_restore.sh` before
starting the container. It also removes inherited ACLs from the embedded
PostgreSQL data directory and restores its required restrictive modes.
